# Gale Research(风力递进调研)

## 参数推断(不问则取默认)

| 参数 | 默认 | 覆盖方式 |
|---|---|---|
| 档位 | **L4**(默认取最深档;成本见 description,轻量需求请显式降档) | 用户点名降档:"随便看看/L1"→L1;"2轮/轻一点/L2"→L2;"3轮/浅一点/L3"→L3 |
| 预算倍率 B | **×1** | 用户说"3倍预算/翻倍预算/多花点"→ 取该倍数。clamp ×1~×5,超出按 ×5 跑并在报告开头声明被 clamp |
| 检查点 | 无(AFK 连续跑完) | 用户说"每轮确认/逐步/停下来"→ 每轮结束展示并等回复 |
| 报告落盘 | `docs/references/<topic>-survey.md`(当前项目);L1 默认不落盘、只交暂存三件套 | 用户指定路径;L1 点名要文件时落简化版,**但仍须保留 meta 行(含停止原因与逐维台账)** |
| 语言 | 跟随用户提问语言 | — |

### 量级契约表(档位=资源配额基准;B 按用户倍率放大封顶,不改变档位身份)

| 档 | 轮次构成 | R1 并行 | R2 深挖上限 | 预算封顶(搜索/抓取) |
|---|---|---|---|---|
| L1 速览 | 仅 R1(三件套即产出) | 3~4 路 | — | ~8 / 0 |
| L2 标准 | R1→R2 | 4~8 路 | 6~8 | ~15 / 10 |
| L3 深度 | R1→R2→R3 终裁 | 4~8 路 | 6~8 | ~22 / 15 |
| L4 扩展(默认) | R1→R2→R3→R4 缺口递归(续轮由可动作缺口决定,无固定轮数;预算只兜底) | 6~10 路 | 10~12 | ~30 / 20 |

**份额取向**:剩余 ≤50% 时优先压缩 R1 新增路径,保留 R2/R3 逐候选核实预算(据 ICLR 2026 非对称核实数据**推算**约 **4 倍**,非实测)。

### 计数口径(台账与校验器共用,不得另立)

- 1 次搜索 = 1 次搜索工具调用 · 1 次抓取 = **1 个 URL**(批量抓取工具一次传 N 个 URL 记 N,不记 1 次)

### 预算台账(每轮开头先读,再决定本轮动作)

- 每轮开始先记一行:`搜索 已用/生效上限` · `抓取 已用/生效上限`,并注明 `生效上限 = 档位基准 ×B<值>`(B 必须显式写出,含 ×1)
- **逐维判定,不跨维合计**:任一维跌破阈值即触发。⚠️ **基准为 0 的维不适用本判定**(如 L1 的抓取维)——0 上限 = 该维不开放,不等于"已耗尽",不得据此触发 exploit
  - 剩余 ≤50% → 转入 exploit:R1 并行压到区间下限;放弃长尾角度;R2 深挖名单按「可证伪且影响选型」排序取前 K
  - 剩余 ≤25% → 不开新候选/新缺口,只做已开项的闭合与终裁
- **预留收束份额**:R3 终裁 + 报告生成锁定 **6 次**调用(推导:R3 目标 = 终选 2~3 个 × (schema 核对 + 定价换算 + 对抗复查) ≥ 2×3 = 6 —— **结构推导,非实测校准值**);R1/R2 单轮支出不得超过当场剩余的 70%(**设计选择**,非实测);轮中触到预留线即停止新增动作,转入 R3 与报告。⚠️ **本条仅 L3/L4 适用**——L1/L2 无 R3,绝对预留会吃掉小档位全部配额
- ⚠️ 台账是**自报**,不是强制(本 skill 无宿主)。违规的唯一兜底 = 它在报告里可见
- 阈值 50%/25% 是**设计选择**(explore→exploit 的分段点,据 BAVT(arXiv 2603.12634) 的定性结论取整),**不是实测值,不承诺校准回填** —— 该二值不随样本变化调整
- 本文件新增/修改的数值阈值须标明是**结构推导**还是**设计选择**;禁用 provisional 这类暗示"待实测校准"的词(会驱动假校准)。⚠️ **本条只管新增/修改的阈值** —— 已发布的档位基准(`~30 / 20` 等)、R1 并行区间(`6~10 路`)、R2 深挖上限**不在其列**

## 停止原因(必须写进报告 meta 行,格式固定为 `停止原因: STOP=<码>`)

触到生效上限(搜索或抓取**任一维**触顶)即停止新增动作,收敛出报告,并按下列之一声明。L1 不落盘时,停止原因与台账两行、外加 §5 缺口裁决表（无可行动缺口时压成一行「无可行动缺口」）一并写进**暂存三件套的对话输出**(不落盘也要给)。

| 码 | 何时用 | 额外必填 |
|---|---|---|
| `SUFFICIENT` | **不存在「未闭合·可动作」缺口**(可能仍有「未闭合·不可动作」) —— 唯一通过证据契约的码 | — |
| `BUDGET_EXHAUSTED` | 触顶 **且** 存在「未闭合·可动作」缺口 | `可动作缺口 N 条` + `建议倍率 ×M` |
| `TIER_LIMIT` | **预算未触顶,但本档轮次结构已到顶**,且存在「未闭合·可动作」缺口(如 L1 只有 R1) | `可动作缺口 N 条` + `建议升档 L<n>` |
| `NO_PROGRESS` | 连续 2 轮可动作缺口零闭合(零进展安全阀触发) | `可动作缺口 N 条` + 仍未闭合缺口清单 |
| `CONTRADICTION_UNRESOLVED` | 存在未消解的矛盾(独立于动作性) | 矛盾条目 |

`×M` 算法:`M = clamp(2, 5, 本轮实际超顶比 × (1 + 可动作缺口数 ÷ 已闭合缺口数))`,分母用**档位基准上限**;**M 即建议的新 B 值**。若 `M ≤ 本次生效 B` ⇒ 改写为「同档位无法收敛,需改口径」。
🔴 `BUDGET_EXHAUSTED` 与 `TIER_LIMIT` 的补救**不同**:前者靠**加预算**(同档位;因为轮次没跑完是钱不够),后者靠**升档**(加钱无用——本档结构上不再有轮次)。不得混用。

🔴 **禁止把"换研究机制"当预算补救**:仅 L4 触顶时建议以 ×M 重跑同档位;改用另一种研究机制(如多角色对抗式)是**机制**差异,不是更大预算 —— 预算不足时不得建议换机制。

## 第 0 步:需求收敛

一句话锁定:调研对象 + 硬性排除条件 + 决策目标(选型/综述)。
关键条件缺失时最多问 2 个问题(文本提问,不用弹窗);能合理推断的直接写进开头声明,继续跑。
例:"只要纯 API,排除必须绑其 CAD 的一体化平台"——这类边界条件必须在第 0 步锁定,后续每轮据此筛除。

## 第 1 轮:广度

- 一次消息内并行 4~8 路 WebSearch:中英双语、按角度拆(术语/头部厂商/长尾厂商/开源替代/垂直行业/算法服务)
- 产出固定三件套,写入暂存结论:
  1. **术语小结**:该领域规范叫法(中/英),含易混淆邻近概念(须区分项)
  2. **候选清单**:每项附初步依据(哪个页面哪句话支撑)
  3. **排除清单**:每项附排除原因——预置的候选也要允许被证伪(搜不到=不存在,如实写"已证伪")
- 🔴 **R2 入选/落选判定表** —— R1→R2 入选判定是**全流程杠杆最大的一步**:此处砍掉的候选,其下游 R2/R3/报告成本一并消失(据 Not Worth Another Token(arXiv 2608.08389) 实测:后验剪枝 −69% token 但质量 −2%;合成前剪枝只省 11.5% 却质量 **+4.9%** —— 两者各有取舍。杠杆在「位置」不在「规则」:**检索前/中停掉则下游成本一并消失,到合成边界才删则上游早已付过**)。
  故必须**逐个候选写明落选理由**,不许默认全数进 R2。入选判据(满足其一):有公开 API/文档页可抓取;声称能力与决策目标直接相关。落选两类:证据不足 → 降级「需商务洽谈」;与硬性排除条件冲突 → 进排除清单。

## 第 2 轮:深挖(逐候选可证伪核实)

对深挖名单按档位契约表上限(L2/L3:6~8 个;L4:10~12 个):

- **证据纪律:只认官方来源**——文档、定价页、API schema 原文。批量抓取用抓取类工具一次多 URL(无批量能力则逐个抓);盲区补少量定向搜索(如中文厂商"公司名+API/二次开发/接口"三连)
- 每个候选回答固定问题:声称的能力在 schema/文档原文里是否可指认?定价形态?集成形态(REST/SDK/桌面中间表)?
- 产出**对比总表** + **关键分化点**:一个决定选型的字段/能力/约束(例:一维切割场景里"多数 API 不感知 miter 切角")
- 无公开文档的候选明确降级为"需商务洽谈",不算核实通过

## 第 3 轮:终裁(仅 L3/L4)

只针对存活的前 2~3 个终选:
- 逐字段核对输入/输出 schema 与用户真实数据的映射
- 定价换算到用户实际用量
- **对抗复查**:主动找"它其实做不到"的证据(论坛抱怨、文档反例、试用限制),而非只看官网
- L4 时终裁最后一步:输出**缺口清单**——每条 = 待证问题 + 产生于哪轮/页面 + 闭合所需证据类型(论坛一手报告/schema 原文/试用限制/商务条款)。后续轮次只许沿此清单动作

## 第 4 轮起:缺口递归(仅 L4)

- 唯一合法输入 = R3 缺口清单(取前 ≤5 条);禁止无缺口锚点的全主题重搜
- 逐缺口定向核实(论坛抱怨/GitHub issues/试用条款/定价页反查/中文盲区三连),证据纪律同第 2 轮
- 产出每条缺口一行,**状态取三态之一**:
  - `已闭合` — 附证据 URL
  - `未闭合·可动作` — 附下一步检索动作(具体查询/来源类型)+ 产生轮次
  - `未闭合·不可动作` — 附 `不可动作:<原因>`(需商务洽谈 / 需试用账号 / 无公开文档),**不要求 URL**
- **续轮条件(三者同时成立)**:存在 ≥1 条「未闭合·可动作」缺口 · 预算未触顶 · 预留份额未被侵蚀
- 轮数由缺口清单决定,**无固定轮数上限**;预算只兜底。可动作缺口 = 0 → 收束

## 报告(固定骨架,落盘)

```
# <主题>调研报告
> 日期 · 方法(档位 L4 · 实际止于 R4 · 停止原因: STOP=SUFFICIENT) · 场景一句话 + 硬性排除条件
> 用量台账: 搜索 11/30 · 抓取 18/20 (生效上限 = 档位基准 ×B1) · 逐轮: R1 搜索 6/抓取 0 · R2 搜索 3/抓取 12 · R3 搜索 1/抓取 4 · R4 搜索 1/抓取 2
> (仅 BUDGET_EXHAUSTED / TIER_LIMIT / NO_PROGRESS) ⚠️ 可动作缺口 3 条 · 建议倍率 ×2 或 建议升档 L3
## 1. 术语对照表(中英)
## 2. 候选对比总表(每格可证伪:有出处才打勾) + 表尾 R2 入选/落选判定表
## 3. 排除清单及原因
## 4. 关键技术判断(分化点 + 落地前必测项)
## 5. 缺口裁决表(全档位必填;L1 不落盘时随对话输出给;`TIER_LIMIT`/`BUDGET_EXHAUSTED`/`NO_PROGRESS` 的声明载体):每行 = 缺口 + 产生于 + 闭合所需证据类型 + 状态 + 证据;无可行动缺口时写一行「无可行动缺口」
## 6. 推荐结论(短期/中期/长期 或 分场景)
## 7. 来源列表(全部 URL)
```

硬性要求:
- 每个"存在/支持 X"的声明附来源 URL;**声明与 URL 同行**,便于机器核对;第三方软文不作为唯一证据
- §5 行的「证据」列按状态取值:`已闭合` 填 URL;`未闭合·可动作` 填下一步动作;`未闭合·不可动作` 填 `不可动作:<原因>`
- 报告为纯文档,写完提议 commit(仅提交报告文件本身)
- 报告落盘后跑本 skill 的 `tools/check_gale_report.py <报告路径>`(`--all <目录>` 批量扫 `*-survey.md`);**BLOCK 项必须修**,WARN 酌情。⚠️ 它只校验自洽性与声明完整性(停止码合法性/台账可解析/互斥规则),**不校验所报数字与 URL 真伪** —— exit 0 ≠ 内容为真

## AFK 纪律

默认不停顿:轮与轮之间不征求同意,直接推进到报告落盘再汇报。
中途发现候选全部被证伪/方向错误:在报告"技术判断"节如实写明,不硬凑结论。
搜索工具故障时改用其他可用的搜索/抓取工具,不空转重试。
**零进展安全阀**:连续 2 轮「可动作缺口零闭合」→ 立即收束,停止码取 `NO_PROGRESS`,并列出仍未闭合的缺口。本阀**不拦保底**:L3/L4 至少完成 R3 终裁;与续轮条件冲突时以本阀为准。与"每轮确认"检查点并存时,闸门结论在检查点交用户裁量。
**收束三件套(缺一不可,任一都不单独托付)**:①边际判据(零进展阀)②预算台账(触顶即收)③停止原因与未闭合缺口在报告中的显式声明。依据:单一停止判据不可信 —— 在线策略由**首次阈值穿越**决定,一个早期假阳性压制其后全部判断。
**边界交接**:需求本质是"多角色对抗 / 多视角矛盾分析 / 发布级" → 说明本技能不适用,提示用户改用相应的研究机制;纯粹"要更多轮/更贵"不算越界 —— 用预算倍率表达即可。
